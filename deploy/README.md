# Развёртывание и ограниченный smoke

**Production news Hermes остаётся в YFC и продолжает работать.**
Новый Hermes Agent **ещё не служба**. Единственное разрешённое выполнение здесь - краткий smoke CLI внутри изолированного контейнера без сети, модели, ключей и публикации. Это не включает Hermes gateway и не даёт автономность.

## Решение владельца, 2026-10-11

Владелец разрешил использовать **действующий выделенный Hermes VPS** для H-01 и расширить swap, если это помогает. На сервере 2 GiB RAM и параллельно работают news Hermes, Reminder Bot/PostgreSQL, proxy и другие службы. Дополнительный swap - страховка, **не** увеличение оперативной памяти.

На хосте вручную добавлен `/swapfile-hermes-extra` 2 GiB (priority -3); прежние `/swapfile1` 2 GiB сохранены, итог 4 GiB swap. Системная настройка `vm.swappiness=20` не менялась. Подтверждены активные news timer/network guard и отсутствие новых сервисов Hermes.

## Проверка допуска

`scripts/host_capacity.py` проверяет на текущем VPS:
- `MemAvailable >= 768 MiB + резерв запуска + 32 MiB`;
- used swap существующей службы `<= 1024 MiB`, load1 `<=1.50`, свободное место `>=5 GiB`;
- в момент начала smoke не выполняется discovery/worker drain.

Важно: это **admission check до старта**, а не гарантия отсутствия гонки с таймером и не непрерывное ограничение ресурсов. Весь процесс дополнительно ограничен Docker `memory=128m`, CPU 0.25, pids=64, network none, readonly fs, no capabilities, non-root, no secrets, volatile tmpfs. Режим предназначен **только для проверки `hermes --version`**.

## Запуск безопасного smoke

Из локальной копии этого репозитория на Hermes VPS, после проверки известного digest и момента относительно новостного таймера:

```bash
# Отдельно под контролем оператора: образ больше 1 GiB сжатым.
docker pull --platform linux/amd64 \
  nousresearch/hermes-agent@sha256:32d095e84190ae7266afbb361579e6921f2c633e899f5eacfb88111b9c851a22

bash deploy/smoke.sh
```

При недостатке памяти script завершится `skipped`; **не** заставлять его проходить снижением резервов. Smoke не запускает LLM, задачу, cron, Telegram или агента как долгоживущую службу. Для полноценной работы необходим отдельный проверенный ресурсный дизайн, новые тесты и решение о модели/ключах.

## Ограничения

- Запрещено запускать upstream `docker-compose.yml` без переработки: он по умолчанию содержит `network_mode: host`.
- Не подключать production `/var/lib/hermes`, `worker.env`, YFC DB, Docker socket или private vault.
- Не использовать paid provider или секреты из YFC.
- Не включать `systemd`, `docker --restart`, auto-deploy и gateway по результату только CLI smoke.
- Для постоянного агента сначала подтвердить наличие RAM headroom и сохранение нормального новостного pipeline в пике.

Образ был действительно загружен и CLI smoke действительно завершился с exit 0. [Протокол](../docs/audits/H-01-on-host-smoke-2026-10-11.md).
