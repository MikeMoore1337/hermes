# H-03 - локальная проверка библиографических записей NCBI

`research_scout.citation_review.review_batch` принимает до 50 уже полученных
через официальный ESummary метаданных. Сам модуль **не выполняет запросы**,
не работает по расписанию, не читает секреты и не публикует новости.

Проверки: URL строго соответствует PMID; разрешён только официальный
`source_api=NCBI_ESUMMARY`, `status=UNVERIFIED_METADATA`, допустимые DOI,
проверенные даты с точностью до дня, отсутствие известных признаков внедрения
инструкций и отсутствия дублей PMID/DOI.

NCBI может возвращать неполные даты, например только год или месяц.
Такие записи получают `HOLD`: приложение не выдумывает день публикации.
Старые, будущие и явно неверные даты тоже остаются `HOLD`.
Свежие записи получают **только** `MANUAL_REVIEW`, никогда
`SCIENTIFICALLY_VERIFIED`. Даже несколько разных PMID могут ссылаться на
связанные исследования, а не подтверждать один и тот же факт.

Выход содержит минимальные библиографические поля, ссылки на PubMed и
проверяемые причины отклонения; научные утверждения не создаются.
Перед включением самостоятельного агента нужны контакт для NCBI, реальная
связность API, правила отбора исследований, проверка независимости,
качества данных и отдельное разрешение на канал публикации.

Ни старый новостной поток YFC, ни отдельный Hermes Agent в этом PR не меняются.
