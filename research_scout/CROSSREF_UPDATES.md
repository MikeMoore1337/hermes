# H-03: поиск corrections/retractions по исходному DOI в Crossref

[Issue #4](https://github.com/MikeMoore1337/hermes/issues/4). Это дополнительный **явный** проверочный инструмент поверх существующих `Europe PMC` и `Crossref`, а не новый фоновый сборщик.

## Почему простая регистрация DOI недостаточна

Старый `research_scout.crossref.verify` обращается к `/works/{doi}` и проверяет, что DOI зарегистрирован, но **не проверяет отсутствие последующих уведомлений**. В Crossref сведения об исправлении могут регистрироваться **в отдельном DOI исправления**, где `update-to` ссылается на исходную статью. Поэтому запрос **исходной** статьи может не содержать полного списка исправлений.

Официальная документация: [Crossref REST API filters](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/) (фильтр `updates`), [Registering updates](https://www.crossref.org/documentation/register-maintain-records/maintaining-your-metadata/registering-updates/), [JSON API format / Update](https://github.com/CrossRef/rest-api-doc/blob/master/api_format.md#update).

## Запуск и бюджет

Без `--execute` сетевой запрос запрещён:

```bash
python3 -m research_scout.crossref_updates --doi 10.1007/s00520-026-11251-3
# {"status":"NOT_EXECUTED","requests_attempted":0}
```

Явный разовый запрос оператором, **после** проверки локальных лимитов и разрешений на VPS:

```bash
python3 -m research_scout.crossref_updates --execute --doi 10.1007/s00520-026-11251-3
```

При этом выполняется **ровно один** read-only GET к `api.crossref.org:443`:

```text
/works?filter=updates:10.1007%2Fs00520-026-11251-3&rows=5&select=DOI,update-to
```

Запрос исключает рефераты/таблицы/текст статьи, ограничен 5 уведомлениями и 48 КиБ JSON, timeout 9 секунд. Нет повторов, перенаправлений, произвольных URL, токенов, стоимости или записи в файловую систему. При ошибке/HTTP 429/некорректном JSON результат `UNKNOWN`, а не «исправлений нет».

**Не интегрировать этот запрос в `daily_digest` без отдельной бюджетной оценки:** там уже действует максимум 5 GET/запуск. Не запускать серии реальных запросов ради демонстрации, без необходимости. Локальные регрессии используют только искусственные заранее фиксированные данные:

```bash
python3 -m unittest -q tests.test_research_crossref_updates
```

## Состояния

- `REVIEW_REQUIRED`: Crossref вернул одно или несколько подходящих уведомлений, включая `CORRECTION_NOTICE`, `RETRACTION_OR_WITHDRAWAL_NOTICE`, `EXPRESSION_OF_CONCERN`, `OTHER_OR_UNKNOWN_NOTICE`. Каждое имеет DOI уведомления и опубликованную дату с исходной точностью, связанную с **исходным** DOI.
- `NOT_FOUND_WITH_COVERAGE`: нет уведомлений **в ответе этого конкретного фильтра Crossref**. Это не научное одобрение, не подтверждение отсутствия уведомлений у издателя или Europe PMC. `authoritative_notice_clearance=false`.
- `UNKNOWN`: запрос или проверка схемы провалились. При расхождении возвращённых связей Crossref с запросом данные не принимаются; это не доказательство чистого статуса.
- `CROSSREF_FILTER_TRUNCATED`: общее число результатов больше возвращённого окна. Дальнейший вывод допускается только после отдельной проверки; автоматической пагинации нет.

Указанные состояния **не меняют** `HOLD/NO_DATA/MANUAL_REVIEW` существующего ежедневного пакета и ничего не повышают до `SCIENTIFICALLY_APPROVED`. Даже если Crossref показывает официальную correction, содержание исправленной статьи и влияние на результаты должен проверить человек.

### Пример уже подтверждённого источником извне

- IRONMAN: оригинал DOI `10.1007/s00520-026-11251-3`; официальное исправление Springer DOI `10.1007/s00520-026-11294-6`, опубликовано **02.10.2026**, исправляет **50 → 150 мин/нед**. В кодовых тестах эта связка - **офлайновая фикстура**, а не утверждение, что реальный Crossref reverse-filter уже её возвращал. Результат живого запроса нужно зафиксировать отдельно.

Для остальных трёх первоначальных статей до выполнения фактической обратной проверки статусы corrections/retractions остаются `UNKNOWN`. Отсутствие найденных сообщений не доказывает отсутствия исправлений.

## Приёмка и безопасность

Проверяются exact DOI matching (case-insensitive), корректность ссылочных DOI, числа результатов, уникальность уведомлений, реальные календарные даты (включая неполные), типы уведомлений и закрытый набор статусов. Сторонние названия, тексты, инструкции/HTML и URL не печатаются и не выполняются. Нет автоматических рекомендаций, публикации в YFC/Telegram, доступа к Second Brain или изменения Hermes H-01 runtime.
