# Hermes #454 - реальный одноразовый Windows native READ worker

Модуль `scripts/h454_native_win32_worker.py` связывает уже реализованные компоненты Hermes:

1. Проверяет настоящий SID текущего Windows-процесса через Win32 `OpenProcessToken` / `GetTokenInformation` / `EqualSid`. Требуется только `NT SERVICE\\HermesCommanderNative`, а не интерактивный пользователь, SYSTEM или LocalService.
2. Читает исключительно фиксированные защищённые файлы `C:\\ProgramData\\HermesCommanderNative\\manifest.json` и `device.json`. Отказывается от reparse-ссылок, hardlink, больших/изменённых файлов. Защищённые NTFS DACL и исходные корни **дополнительно обязан проверить родительский SCM-процесс** через `NativeHostAdmission`; один SID не доказывает DACL.
3. Проверяет SHA-256 установочного манифеста, точный SHA исходников, новую Win32-идентичность, пять утверждённых оригинальных READ-корней и срок жизни.
4. Расшифровывает bearer именно через Windows DPAPI CurrentUser под виртуальной учётной записью службы. Интерактивно зашифрованный токен не переносится в контекст службы.
5. Проверяет текущий owner-bound bearer у существующего BRC HTTPS-эндпоинта. При отсутствии доступа к серверу, отзыве/ротации токена, неверном сертификате или ответе отказывает в работе.
6. Подключается по `wss://hermes.mikemoore.top/ws` через существующий транспорт с правильным H454 HELLO. Дальше только `native_file_stat`, `native_file_read` и `native_file_list` по прежнему проверенному Win32 handle-bound адаптеру. Каждый обмен дополнительно проверяет SID, срок действия, разрешение владельца и отзыв.

CLI допускает только `--run-once --release-sha <точный SHA>`. Нельзя передать токен, дополнительные каталоги, URL, имя устройства, список команд или отключить проверки.

**На текущем этапе это исполняемый Python-код, а не готовый установленный exe.** В существующем MSI пока находится только .NET SCM-служба с режимом `NOT_PROVISIONED`. Следующий этап должен включить проверенную, подписанную доставку worker вместе с его зависимостью `websockets` и жёстко ограниченный запуск worker из службы под тем же SID. Без подписанного выпуска и проверенного владельческого состояния запуск остаётся запрещённым.

CI выполняет реальные Windows Token API проверки отказа для чужого пользователя и полный синтетический WSS-протокол (в том числе повторный отзыв) без чтения оригинальных проектов. Production, Windows ПК владельца и VPS не изменены; Issue #454 открыта.
