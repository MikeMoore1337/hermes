## Детерминированная проверка

```sh
python3 scripts/check_markdown_links.py
```

Нужен только Python стандартной библиотеки. Автоматически проверяются существование относительных файлов/каталогов, локальные якоря, попытки выхода за корень репозитория, абсолютные и небезопасные локальные пути, символические ссылки на внешние файлы. Текст в fenced/inline коде пропускается. Диагностика показывает только относительный путь, номер строки и заранее заданный код причины, не выводит URL с потенциальным токеном.

Результат первого запуска по `main` и новым проверкам: **68 Markdown-файлов, отсутствие ошибок локальных targets/anchors**. Отдельно после добавления кода пройдены **601/601 offline unit tests** в Linux-контейнере. В CI команда включена до тестов, без вызова HTTP, платного провайдера и дополнительных зависимостей.

## Ограничения

Markdown - сложный формат: регулярный шаблон покрывает стандартные inline links `[text](file.md#anchor)`, а не полную спецификацию CommonMark, HTML links и ссылочные определения `[text][ref]`. Проверка якорей приближает GitHub slug для типовых заголовков; сложные HTML и пользовательские ID требуют отдельного рассмотрения. **Не выдавать локальный PASS за доступность внешних страниц или корректность научных выводов.**

Статусы внешних HTTP (403, 404, 429, временные 5xx, redirect, timeout) требуют отдельной явной bounded read-only проверки только разрешённых публичных адресов. Она не должна блокировать обязательный CI при недоступности внешнего поставщика и не должна обращаться к private GitHub/YFC/Telegram/Second Brain.
