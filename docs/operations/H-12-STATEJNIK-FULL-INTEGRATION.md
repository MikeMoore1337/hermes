## Права и первичные файлы

Владелец Hermes сообщил, что автор лично подарил ему проект и **полную
лицензию** на использование, модификацию и перенос. На этом основании
можно проводить полную адаптацию для его Hermes / YFC. Исходная публичная
`LICENSE` с пометкой `All rights reserved` оставлена **без изменений**.
Частное разрешение заявлено владельцем, оригинал правового документа здесь
не опубликован и независимо не проверялся. Настоящая запись не лицензирует
проект третьим лицам.

В `third_party/statejnik/` скопирован **весь отслеживаемый Git состав
upstream**: README, CHANGELOG, LICENSE, .gitignore, исходный
`skills/statejnik/SKILL.md`, все 8 процессных модулей, методология,
чек-листы, 17 Python-скриптов (12 CLI + 5 вспомогательных), шаблоны
конфигурации/промптов и три исходных тестовых файла. Ничего не удалено,
не переписано и не заменено укороченной имитацией.

`third_party/statejnik/HERMES_SOURCE_MANIFEST.json` хранит SHA-256
каждого из **62 upstream-файлов**, имя автора и commit. Команда
`python -m statejnik_integration.provenance` проверяет их байтовую
целостность. Это хеши сохранённой копии, **не подписанная supply-chain
аттестация** upstream и не проверка всей безопасности чужого кода.

## Интеграция и безопасное исполнение

Новая штатная интеграционная оболочка:
`python3 -m statejnik_integration.runner`. По умолчанию она только
возвращает каталог **12 CLI entrypoints** и перечень ограничений,
ни один upstream-скрипт не исполняется. Если пользователь намеренно
запускает локальную проверку:

```bash
python3 -m statejnik_integration.provenance
python3 -m statejnik_integration.runner
# Создать отдельную пустую рабочую папку заранее, не домашний каталог / vault.
python3 -m statejnik_integration.runner --init-workspace --workspace /path/to/empty-statejnik-workspace
python3 -m statejnik_integration.runner --execute --tool status --workspace /path/to/empty-statejnik-workspace -- --help
```

Последняя команда предназначена **для отдельного тестового Docker-хоста**,
где уже есть exact `nousresearch/hermes-agent@sha256:a11574b7...`
в локальном кеше. Не ставить Docker image ради этого на рабочий Hermes VPS.

Исполнение только через Docker argv без оболочки, pinned digest,
`--pull=never`, `--network none`, `--read-only`, `--cap-drop ALL`,
`--security-opt no-new-privileges`, nonroot, CPU/memory/PID limits,
только vendor source как read-only bind и **одна вручную выбранная рабочая
папка**. Переменные Wordstat, Telegram, WordPress, YFC, приватные секреты
не передаются. У subprocess нет ретраев и есть timeout. Захват stdout
ограничен 64 KiB, stderr — 16 KiB непосредственно во время чтения;
при превышении лимита процесс и его дочерняя группа останавливаются.
Вместо наследования переменных хоста дочерний процесс получает только
явно сформированный PATH; секреты хоста не передаются даже на уровне
Docker CLI. Любая ошибка возвращает постоянный обезличенный код,
а не stderr / содержимое статьи. Содержимое пользовательской статьи
не попадает в вывод общего каталога Hermes.

Этот sandbox — **ограниченный локальный режим** для проверки скриптов,
не разрешённый resident Agent. 8 offline entrypoints могут исполняться
вручную, 3 инструмента сбора источников и 1 инструмент публикации
отклоняются ещё до запуска Docker. Они **не удалены**: полный код
сохранён, но наружные функции заблокированы до отдельного GO. Указанный
Docker image всё ещё имеет известный H-01 issue #33: Python 3.14.7 /
неподтверждённую attestation; на production его не запускать.

Сохранённый оригинальный `SKILL.md` — *недоверенный исходный материал*,
не помещён в активный каталог skills Hermes. Он не может сам назначить
себе роли, API-разрешения, широкие OS tools или право публикации.

## Проверки и статус допуска

- Исходные тесты upstream: **62/62 PASS** в отдельном nonroot networkless
  Linux Docker; фактические execution results прилагаются к PR.
- Целостность SHA manifest, все CLI, 8 стадий, шаблоны и исходная лицензия,
  строгая Docker argv / отсутствие привилегий / отключение публикации,
  malformed workspaces и аргументы проверяются тестами Hermes.
- Все результаты offline не являются проверкой актуального Wordstat,
  настоящих конкурентов, CMS/MCP, юридической точности, корректности
  научных выводов или реального end-to-end workflow.
- При объединении PR допустимо доставить **полный исходный комплект** в
  версионированный release snapshot VPS, но **не устанавливать/активировать
  `SKILL.md` и не запускать контейнер/сетевые или publish scripts**.
- **H-12 HTML metadata:** [парсер публичной HTML-страницы и ручной
  handoff в site-gap](H-12-PUBLIC-HTML-METADATA-PILOT.md) работают на
  синтетических байтах; живой сетевой сбор не подключён.
- **H-12 site-gap:** [строго офлайн-сопоставление тем и существующих
  статей](H-12-STATEJNIK-OFFLINE-SITE-GAP.md) теперь доступно вручную
  как отдельная `site-gap`; сетевой `site scan` остаётся заблокирован.
- **H-12 Wordstat V2:** [официальный API, требования IAM и прайс,
  офлайн-контракт и запрет расходов](H-12-WORDSTAT-V2-ADMISSION.md).
  Старый клиент vendor `WORDSTAT_TOKEN` не запускается.
- **H-12 network candidate:** [отдельный отчёт об SSRF/DNS rebinding,
  pinned TLS и отрицательных тестах](H-12-STATEJNIK-NETWORK-BOUNDARY.md).
  Он не подключён к upstream runner: реальная сеть остаётся запрещена.
- Для реального полного запуска следующая стадия: отдельный security review
  `_net.py` (особенно SSRF/DNS fallback и default `allow_private=True`),
  hardened secrets, host/network/billing fences, Wordstat permissions,
  YFC SEO ownership, test site/live proof, утверждение публикации.

**Текущий статус:** `FULL_SOURCE_IMPORTED`,
`OFFLINE_VALIDATION_AVAILABLE`, `NETWORK_AND_PUBLISH_BLOCKED`,
`RESIDENT_AGENT_NO_GO`. Это полное внедрение кодовой базы, не
автоматическая активация всех сторонних интеграций.
