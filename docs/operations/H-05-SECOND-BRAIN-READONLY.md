## Offline-only implementation

`second_brain_readonly.offline_adapter` is explicitly **not a production connector**.

- Default invocation is disabled. To demonstrate synthetic tests, callers must pass `allow_mock=True`, a signed test-only `MockGrant`, an explicit UTC clock and an exact `MockTransport` instance.
- Only one demo identifier of the form `F-demo-...` can be requested. No URLs, local paths, free-form search, pagination, arbitrary operations or wildcard scopes.
- Mock claims bind `hermes-h05-offline`, `second-brain-mock-only`, `status.read`, `synthetic-status:read`, one resource, expiry and non-revocation. Offline HMAC verifies tampering, using a synthetic test key provided by the caller; **this is not an approved credential format** and must never be reused for production.
- Authorization is checked before calling the in-memory transport. Missing, forged, expired, revoked, mismatched identity/audience/scope/resource grants are rejected with fixed reason codes.
- In-memory transport accepts at most eight synthetic response slots, two requests over its lifetime, one response per request, no retries; responses are limited to 2048 bytes. Timeouts and HTTP error codes are **simulated**. This is not real network rate limiting, TLS, DNS protection or HTTP enforcement.
- Strict JSON object schema rejects extra fields, unknown enum values, duplicate keys, mismatched resources, future evidence, expired response, and `READY` combined with unknown/stale/revoked provenance/source or nonempty reason codes. Invalid responses do not return raw JSON.
- Result contains only `mode=MOCK_ONLY`, `integration_verified=false`, access/integration status and approved metadata. No note body, vault links/paths, model calls, credentials, file writes or database/cache.
- No runtime import, service, timer, MCP registration or feature flag activation is added. The existing integration registry remains `DEFER`.

**Quality separation:** `access_status` indicates synthetic authorization; `source_status`, `freshness_status`, `provenance_status`, `quality_status` preserve separate server-like statuses; `integration_status=MOCK_SUCCESS` only means one mock read was decoded. HTTP success can never establish factual truth. H-11 quality rules remain a separate offline-only audit. Fake statuses are NOT a canonical Second Brain API contract.

## Test and side-effect contract

Run:
```bash
python3 -m unittest discover -s tests -p test_h05_second_brain_readonly.py -v
python3 -m unittest discover -s tests -v
```

The deterministic tests cover 12 numbered synthetic end-to-end scenarios (current fact; insufficient provenance; stale; revoked source; contradiction; nonexistent; expired credentials; forged scope; other resource; forbidden write and enumeration; mocked failures/timeouts; private-field rejection). Additional negatives cover disabled-by-default, identity/audience, revocation, 401/403/404/429/5xx, redirects, invalid JSON, duplicate JSON keys, unknown schema, size, expiry, anomalous statuses and resource budget.

Tests inject only in-memory byte strings, never a vault path or network destination. They patch file/socket/process creation during the positive read, assert deterministic responses and no mutation of synthetic fixtures. There is no LLM invocation path. This test cannot prove a real server has no write side effects; that requires a separate server-side acceptance test.

## Proposed Second Brain external contract (separate owner-approved task)

Before any live Hermes code, Second Brain owners must authorize, version and implement **one** minimal external **metadata-only** endpoint and server-side identity/scope enforcement, or designate an already-existing equivalent after a fresh audit:

1. A fixed HTTPS authority, exact path and method; one fact/status per request, no arbitrary note retrieval, search, write or vault listing. Exact transport request/response schema, closed enums, unambiguous temporal semantics, compatibility and version-rejection policy.
2. Independent service identity, intended audience, non-wildcard read scope and resource allowlist, issuance/rotation, TTL, server-validated revocation, deny-before-retrieval on every request. No browser OAuth cookie, no new token issued as part of #6.
3. Only opaque IDs and safe statuses: provenance, source, freshness, permission, quality, reason codes, checked_at/expires_at. Owner must explicitly decide whether any note text is ever allowed (default: none). No public endpoint or public model export.
4. Server quota and bounding: payload, records, concurrency, timeouts, per-identity request rate, no unsafe pagination; authenticated audit without note body, identifiers, secret values or source paths.
5. Security proof: exact endpoint TLS, DNS/IP/SSRF/metadata-address rejection, no redirects, safe 401/403/404/429/5xx, no inferred truth after failure; server and client negative tests, actual privilege enforcement, privacy testing and rollback.
6. Contract signature/version and owner approval must be documented in Second Brain independently of Hermes. Never deploy a new endpoint to bypass #386.

After approval, implement a **separate** fixed-endpoint network adapter; do not extend this mock module to take arbitrary URLs or general-purpose transport callbacks.
