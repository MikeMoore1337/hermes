# Ponytail v5.3.2 - только среда разработки Hermes

[Issue #630](https://github.com/MikeMoore1337/hermes/issues/630) | [Официальный репозиторий](https://github.com/DietrichGebert/ponytail) | [Инструкция upstream](https://github.com/DietrichGebert/ponytail/blob/v5.3.2/INSTALL.md)

## Назначение

Использовать **оригинальный** Ponytail как необязательный инструмент для написания и проверки кода Hermes, а не как новый runtime-компонент. Применимо к Codex Desktop и любому другому официально совместимому клиенту, если подключение им действительно поддерживается. Не заменяет `AGENTS.md`, `docs/security/THREAT_MODEL.md`, `docs/architecture/OWNERSHIP.md`, GitHub Issue, существующие навыки Toolkit и обязательные проверки.

Источник: официальный тег `v5.3.2`, SHA `16352ac229eb08a9598dcae48fe9f2b342567d86`, лицензия MIT. Этот SHA уже указан в публичном `MANIFEST.json` AI Development Toolkit. Референсная копия шести **неизменённых** оригинальных `SKILL.md` подготовлена в [Toolkit PR #428](https://github.com/MikeMoore1337/ai-development-toolkit/pull/428) под `third_party/ponytail-v5.3.2/skills/`; пока PR не объединён, его нельзя считать релизом Toolkit.

## Подключение

- **Уже установлен официальный Ponytail в агенте разработки:** использовать единственную текущую host-установку. Не копировать в Hermes и не создавать fork.
- **Codex Desktop на машине владельца:** без Codex CLI и без платных API допустимо только ручное копирование оригинальных каталогов навыков в `%USERPROFILE%\.agents\skills\` через Проводник Windows из проверенного upstream SHA. Перезапустить клиент, проверить, что навыки доступны, и выполнить ограниченный ручной пробный вызов. Это **skill-only**, не официальный плагин с автоматическими lifecycle hooks. Фактическое обнаружение, активация и оценка результата здесь **NOT_VERIFIED**.
- **Полноценный официальный плагин для других пользователей:** соблюдать upstream `INSTALL.md`. Его требования к клиенту, установщику и hooks проверяются отдельно; допустимость сторонних CLI определяется правилами пользователя, не личными ограничениями владельца.
- Не включать Ponytail автоматически в каждую задачу. Вызывать `ponytail-review` и `ponytail-audit` только по необходимости. `ultra` - исключительно по явному запросу.

## Строгая граница resident Hermes Agent

Upstream поддерживает отдельную установку `hermes plugins install ... --enable`. **НЕ выполнять** её в этом Issue и НЕ переносить в `skills/`, VPS, runtime agent, systemd, Docker, MCP, BRC, SSH, gateway или общие hooks. В отличие от dev-only инструкций, resident plugin исполняется в доверенном процессе и может получить его реальные полномочия. Требуется отдельный предметный owner approval и runtime security check: provenance, permissions, OS isolation, egress, stop/rollback, logs и негативные тесты.

Эта документация не разрешает Codex CLI владельцу, Claude CLI, расходы, дополнительные агентные обзоры, отправку данных, секреты или публикацию материалов. Текущие обязательные тесты, проверки безопасности и workflow Hermes сохраняются.

## Проверка и откат

1. Перед использованием проверить `v5.3.2`, SHA и MIT-лицензию у исходного автора; проверить наличие дубликата в клиенте.
2. Проверить видимость оригинальных навыков и один узкий dev/QA-сценарий на не секретных данных. Отсутствие наблюдения фиксировать как `HOST_NOT_VERIFIED`; отсутствие успешного вызова - `L5_NOT_VERIFIED`. Проверка документов не равна проверке runtime.
3. Откатить можно удалением только каталогов Ponytail, добавленных оператором вручную. Не трогать ранее установленный официальный плагин или навыки Toolkit.
4. Для изменения репозитория проверить GitHub PR и exact-head CI. Это не требует перезапуска Hermes Agent. Если меняется только документация, **production runtime unchanged**; состояние VPS не выводится из CI.
