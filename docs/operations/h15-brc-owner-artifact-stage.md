## Hermes #454 — одношаговая подготовка образа BRC на Docker-хосте

Скрипт scripts/h15_brc_owner_artifact_stage.py не использует Codex CLI и не передаёт BRC-доступ к Docker-хосту. Он через авторизованный бесплатный GitHub CLI выбирает успешную сборку ровно для текущего main SHA, читает независимые контрольные суммы из журнала того же CI-запуска, загружает единственный OCI-артефакт в приватную папку владельца и проверяет файлы штатной offline-проверкой. Повторный запуск не перезаписывает уже проверенный архив.

По умолчанию действие ТОЛЬКО скачивает и проверяет OCI. Опция --load доступна лишь root и дополнительно запускает существующий верифицированный загрузчик Docker-образа; она дополнительно проверяет текущий запущенный relay ранее утверждённой read-only проверкой допуска; не останавливает и не запускает relay. Реальное обновление требует отдельного root-owned решения владельца и scripts/h15_brc_transactional_upgrade.py. Действующие SQLite, OAuth, устройства и Caddy не трогаются.

Пример, выполняемый непосредственно на разрешённом Docker-хосте после установки и авторизации gh под вызывающим пользователем:

    python3 -m scripts.h15_brc_owner_artifact_stage --directory /PRIVATE/OWNER-STAGING

Директория должна существовать, принадлежать вызывающему пользователю и иметь права 0700. Для --load нужны также root, docker и zstd. Не передавайте GH_TOKEN или другие ключи в чат, журналы и команды с открытым вводом. Если в main нет свежей успешной закреплённой сборки или архив протух, скрипт откажет без отката к прошлому SHA. Дополнительные тесты: python3 -m unittest tests.test_h15_brc_owner_artifact_stage -v.


### Версия `main` изменилась после сборки

Образ всегда проверяется относительно своего **фактического source SHA**, указанного
в CI-манифесте. Если после успешной сборки в `main` влились только **посторонние
для BRC изменения**, загрузчик может использовать этот источник вместо
повторной тяжёлой сборки. Обязателен ответ GitHub Compare: источник -
подтверждённый предок текущего `main`, не более 80 коммитов, неполный
или усечённый diff отклоняется. В сравниваемом диапазоне запрещены
изменения и переименования путей `deploy/h15/`, `scripts/h15_`,
`tests/test_h15_`, `docs/security/h15-brc*`, связанных файлов
зависимостей и самого workflow кандидата.

В выводе отображаются **оба SHA**: `source_sha` образа и
`current_main_sha`, а также `ancestor_candidate_reused`. Это не
пересборка на более новый коммит и не ослабление OCI-проверки: подпись
файлов, контрольные суммы и выпуск всё равно строго привязаны к
`source_sha`. Любое изменение BRC требует новой сборки.
