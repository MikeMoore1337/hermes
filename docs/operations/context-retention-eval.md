# H-29 / #466 - Контекст после сокращения: синтетическая проверка

**Решение:** `EVAL_ONLY` / использовать существующий `hermes_benchmark` и
отдельный namespace `hermes_context_eval`. Не внедрять новый компрессор
в Hermes BRC, VPS, Control Center, Codex или resident Hermes Agent.

## Текущий потребитель и границы исследования

Существующий `hermes_benchmark/` (#273) уже проверяет цикл задач,
неподтверждённый CI и доставку, отказ от полномочий и восстановление после
ошибок. `hermes_toolperf/` (#463, #480, #464) тестирует отдельные вызовы и
метаданные инструментов. #291 отвечает за отдельный live-canary admission gate.

В доступном исходном коде Hermes **не обнаружен самостоятельный
подтверждённый продакшн-компрессор истории**, для которого можно безопасно
добавить production adapter. Сеансы BRC/сервер в рамках #466 не открывались,
реальные модели и приватные чаты не читались. Поэтому никакой новый runtime
consumer, endpoint или background timer здесь не создаётся.

Upstream методический ориентир:
`NousResearch/hermes-compression-eval`, reviewed
`main` tree `b65773b401874863b3dab94d6b0bd3d19fd95688`.
GitHub repository license metadata не подтверждает разрешения копировать
отдельные файлы. **Ни код, ни данные, ни реальные dialogue fixtures
upstream не копировались.** Здесь оригинальный небольшой synthetic corpus.

## Контракт проверки

`hermes_context_eval/cases.py` содержит девять полностью вымышленных
историй и **отдельно записанные ожидаемые состояния**. У каждой истории
уникальный `case_id`, `version=1`, категория, входные события и эталон.

Сценарии:

| Случай | Что обязано сохраниться после восстановления |
| --- | --- |
| cx-01 | Слияние PR и CI PASS **не означают** production deploy |
| cx-02 | Последний зафиксированный отказ владельца отменяет прежнее разрешение |
| cx-03 | CI failure не превращается в PASS от заявления агента |
| cx-04 | Потеря связи с устройством не означает завершение операции |
| cx-05 | Нулевой бюджет и запрет `paid_api`, `codex_cli`, `remote_shell` не исчезают |
| cx-06 | CI другого SHA не является подтверждением текущего SHA |
| cx-07 | Неподтверждённое противоречивое заявление об approval не обходит отказ |
| cx-08 | Заявление `DEPLOYED` без действительного receipt не считается доставкой |
| cx-09 | Контрольный позитивный сценарий требует *всех* synthetic CI/merge/deploy receipts |

Состояние содержит `issue`, `branch`, точный `sha`, `owner`,
`ci`, `merged`, `deployed`, `device`, бюджет и запреты,
неразрешённые критерии и идентификаторы доказательств.

Строгий replay: `serialize(events)` → deserialize →
структурная проекция только из явных событий → `serialize(summary)` →
deserialize → независимый oracle. Истина в `expected` задана отдельно,
а не получена от функции-кандидата. Поддельные claims регистрируются как
`UNVERIFIED_*`, но никогда не изменяют статус. Враждебные изменения SHA,
решения владельца, бюджета, ссылки или последнего статуса отвергаются.

`baseline` намеренно хранит только номер задачи и общую фразу «done»,
поэтому ожидаемо проваливает oracle. `candidate` - детерминированная
lossless *structured state projection*, **не вызов модели**.
У candidate нет гарантии уменьшения числа байт: `input_bytes` и
`summary_bytes` сообщаются фактически. Отчёт не объявляет
увеличение скорости или качество LLM из синтетических PASS.

Строки доказательств с URL `github.com/MikeMoore1337/hermes` и номера
8801/8802/8803 - **фиктивные идентификаторы**, служащие форматом, а не
реальными GitHub job receipts.

## Воспроизведение и критерий качества

Из корня репозитория без дополнительных зависимостей:

```bash
python3 -m unittest tests.test_hermes_context_eval -v
python3 -m hermes_context_eval.core --sha "$(git rev-parse HEAD)"
```

Обычный GitHub quality workflow вызывает второй скрипт и фиксирует
`9/9 PASS` и SHA-256 всего корпуса. Дополнительные негативные тесты
проверяют false deployment, отменённый approval, неполный CI, stale SHA,
потерю обязательных полей, неверное JSON и отсутствие вызовов сети/process.

Подтверждение: только `OFFLINE_SYNTHETIC`. Качество реального
сокращения Hermes / Claude / ChatGPT / Codex - `NOT_MEASURED`.
Фактический BRC memory, real provider spend, deployment receipt и
пользовательские private sessions - `NOT_RUN`. Любая будущая online
фаза потребует отдельного zero-extra-cost GO и не входит в этот выпуск.

**Rollout:** только исходники и тесты, не подключать новый компрессор;
не изменять ни resident Hermes Agent #33, ни BRC #454, ни допуск #291.
