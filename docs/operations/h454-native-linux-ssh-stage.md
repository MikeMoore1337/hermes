# Hermes #454 Stage 2A - restricted Linux SSH source staging and cleanup

Stage 1 is a source-only nonprivileged SSH delivery channel for an
exact-SHA Linux original-read source bundle. It is NOT a running native
agent, an installer with root rights, an SSH tunnel with shell access, or
a second MCP server. Host deployment is separately owner authorized.

## Operator roles and controls

- Target label: hermes-vps or yfc-vps, never a Docker sandbox.
- Each VPS has its OWN nonroot, non-sudo, no-shell account
  h454-native-stage. Its forced authorized_keys entry must use the
  restrict option (no PTY, forwarding, agent forwarding, X11 or
  arbitrary commands) and a root-owned immutable wrapper invoking the
  reviewed module with one FIXED --target argument. The SSH_ORIGINAL_COMMAND
  must be literally stage or cleanup. Neither SSH caller nor payload
  chooses the Linux account, state directory, original project root or
  subprocess to execute.
- The fixed host inbox /var/lib/hermes-commander-native-staging has
  mode 0700, is owned by h454-native-stage and has root-owned safe
  ancestors. No other account can write it.
- One canonical bounded JSON frame contains only existing exact SHA,
  target label, SHA-256, bundle and verifier receipt. Archive content
  is rechecked by the already reviewed strict bounded USTAR verifier
  against the exact ten source files. No tar extraction is performed.
- The nonroot stage command exclusively creates two private 0600 files
  in an exact release subdirectory. It cannot call sudo, systemctl,
  useradd, deploy, Docker, network listeners, shell, or read original
  project files. A duplicate release/refusal preserves the old files.
- Cleanup accepts only the same exact verified source archive and
  release/receipt bytes. It refuses a changed file, symlink or new
  member and never removes a different release. These are STAGING
  files only, not the owner's source trees.
- The existing scripts/h454_native_linux_install_off.py is a separate
  ROOT INTERACTIVE TTY installer/rollback. It can install only an
  offline disabled network-denied systemd preflight unit. It is not
  callable via this SSH account. A later privileged handoff from
  staged blobs into root-owned private state requires a separate
  exact host approval and proof.

## Manual GitHub Actions workflow (NOT run)

.github/workflows/h454-native-linux-ssh-stage.yml is manually dispatched
on main with source SHA, target, and stage/cleanup action.
It requires successful main Repository + UI CI and an owner-reviewed
target-specific GitHub Environment:

- Hermes VPS: h454-hermes-native-stage
- YFC VPS: h454-yfc-native-stage

Each Environment separately needs owner reviewer protection, the
variable H454_NATIVE_STAGE_OWNER_APPROVED=true after owner approval,
and secrets H454_NATIVE_STAGE_HOST, H454_NATIVE_STAGE_KEY,
H454_NATIVE_STAGE_KNOWN_HOSTS. The secrets must not be sent in chat,
committed to GitHub or re-used from HERMES_DEPLOY_KEY. The SSH known_host
must be verified out-of-band, not generated by insecure ssh-keyscan
inside the workflow.

The GitHub job builds the exact main SHA source archive, verifies it,
sends only one bounded stdin blob to the dedicated forced SSH command,
checks a fixed-schema sanitized response and uploads a short-lived
nonsecret receipt. It does NOT request sudo or root installation,
upload any owner tokens, or change existing BRC/WSS.
