## Дополнительный тестовый контракт H-480

Реализован в `hermes_toolperf/call_contract.py` и **не экспортируется как
компонент реального MCP**. Демонстрационные инструменты называются
`mock.read_file` и `mock.write_file`, имеют только виртуальный файл
`docs/note.txt`, устройство `synthetic-device` и scope `workspace:docs`.
Фиктивное `grant-owner-reviewed` **не является реальным разрешением**.

Фиксированная JSON-оболочка версии 1:

- `schema_version`, `attempt_id`, `tool_call_id`, `approval_id`,
  `idempotency_key`, `deadline_epoch`, `depth`, `step`,
  `device_id`, `scope`, `tool`, `arguments`.
- Неизвестные/отсутствующие поля, лишние аргументы, дублирующиеся JSON-ключи,
  некорректные типы, нечитаемые данные, `NaN`, alias и подмена пути запрещены.
- Единственный разрешённый побочный эффект - изменение строки во **внутреннем
  Python-словаре**; файловая система, сеть и subprocess не используются.
- Вызовы ограничены четырьмя попытками на виртуальную сессию, глубиной не
  более 1, сроком запроса до 300 секунд и выводом до 128 байт.
- `approval_id` обязателен для виртуальной записи и равен `null` для чтения.
  В production такое текстовое поле **не** доказывает разрешение:
  необходим реальный операторский ACL и доверенный источник grants (#350).
- Если эффект уже применён, но подтверждение потеряно, состояние `UNKNOWN`;
  повтор с прежним `tool_call_id` либо `idempotency_key` запрещён, а новая запись с другими ID также блокируется до отдельной сверки неопределённого эффекта.
- Отмена до эффекта ничего не меняет; повтор после отмены также не разрешён.
- Независимый виртуальный журнал связывает `tool_call_id` с фактически
  записанным/прочитанным значением: ненадёжный `status=ok` не создаёт receipt.

## Версионирование и проверки

`hermes_toolperf/fixtures/tool-calls-v1.json` - 18 отрицательных кейсов,
`hermes_toolperf/call_cases.py` - фиксированное воспроизведение.
Каждый case имеет ID, ожидаемый reason code и SHA-256 своего канонического
JSON. Отчёт содержит SHA-256 всего набора и отделяет:

- `PASS/FAIL` - виртуальный переход и отсутствие запрещённых побочных эффектов;
- `NOT_VERIFIED` - реальный Hermes BRC, native MCP transport и OS ACL;
- `NOT_MEASURED` - эффективность/расходы реальных моделей и устройств.

Запуск без инструментов и API:
```bash
python3 -m hermes_toolperf.call_cases
python3 -m unittest tests.test_tool_call_contract -v
```
Обе команды являются только офлайн-тестами; CI запускает их совместно с
остальной регрессией на exact GitHub SHA.

**Источник методов:** NousResearch/Hermes-Function-Calling и текущий
NousResearch/hermes-agent (референсы, не новые зависимости).
Ни один файл из чужого репозитория не копировался; источник лицензии кода
не использовался как разрешение на перенос.

## Ограничение приёмки

Для данного этапа - **IMPLEMENT_MINIMAL_FIX** (тестовый контур).
Реальные изменённые BRC-полномочия и MCP dispatch **НЕ ПРОИЗВОДИЛИСЬ**.
Перед использованием в реальных инструментах необходима отдельная
реализация правил в действующем доверенном обработчике, независимые
проверки фактического OS/network side effect, одобрение #350 и
эксплуатационная проверка на разрешённых устройствах.

Нельзя выдавать синтетическое `PASS` за отсутствие уязвимостей
на работающем сервере или за проверенное разрешение владельца.
