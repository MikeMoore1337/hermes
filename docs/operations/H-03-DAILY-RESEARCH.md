# H-03 - ежедневный публичный библиографический отчёт Research Scout

[Issue #4](https://github.com/MikeMoore1337/hermes/issues/4). Источники - **только Europe PMC и Crossref**, HTTPS метаданные, без NCBI-регистрации, API-ключей, карты, платного тарифа, языковой модели или импорта в YFC. Это **отдельный** модуль, не трогает существующие новости и редакционный бот.

## Что делает

- До трёх строго фиксированных запросов Europe PMC в сутки: силовые тренировки, гипертрофия мышц, восстановление; фиксированное окно последние 30 дней и максимум 2 записи по теме.
- Если найден DOI подходящего для ручной проверки кандидата, выполняет **не более одного** Crossref DOI lookup и **не более одного** дополнительного запроса Europe PMC core `/article/MED|PMC/id` для того же кандидата. Итого максимум **5 GET за проход**, без retry, redirects, ключей, авторизации или платных источников. Остальные кандидаты имеют `article_notice_state=NOT_CHECKED`.
- При обнаруженном `commentCorrectionList` с исправлением/отзывом или неопознанной записью устанавливает `article_notice_state=REVIEW_REQUIRED` и `status=HOLD` для проверенного кандидата. Ошибка источника или несоответствие DOI также оставляет `HOLD`. При отсутствии сообщения состояние `NOT_REPORTED_IN_THIS_METADATA`, а **не** доказательство отсутствия исправления.
- Делает минимальный локальный отчёт `/var/lib/hermes-research-scout/latest-citations.json` (каталог `0700 root`, файл `0600 root`). В отчёте: временная отметка, открытые библиографические ссылки, заголовки, DOI, статус, причины HOLD, отметка подтверждения *регистрации DOI*, но **не научной истины**.
- `MANUAL_REVIEW` означает «нужна проверка научного оригинала», `HOLD` означает недостаточные либо небезопасные сведения, `NO_DATA` означает отсутствие доступных кандидатов. Отсутствие DOI, ошибка одного источника или повтор статьи в разных темах не превращается в независимое доказательство.
- В журнал systemd выходят **только статусы, числа кандидатов и количество запросов**, ни сырые заголовки, ни токены, ни медицинские советы. Никаких сообщений третьим лицам, Telegram-публикаций, редакционных действий, вызовов модели, обновлений сайта, GitHub write.

## Безопасная эксплуатация

```bash
python3 -m research_scout.daily_digest
# NOT_EXECUTED

# Отдельно проверенный и разрешённый хост:
sudo bash /opt/hermes-agent-owner/deploy/install-research-scout.sh
systemctl status hermes-research-scout.timer --no-pager
journalctl -u hermes-research-scout.service --no-pager -n 20
```

Установщик не изменяет новостные timers, а лишь проверяет их активность. Служба sandbox systemd без Linux capabilities, без доступа к приватным каталогам YFC/Ops/QA/GitHub tokens, защищена по RAM/CPU и времени. По умолчанию один запуск при включении таймера через ~2 минуты для проверки, затем ежедневно около **19:30 по времени VPS (МСК)** с возможной задержкой до пяти минут; `Persistent=false`, никаких догоняющих повторов после простоя. Первоначальный явный GET до включения расписания обязателен.

Отключить только новый Research Scout (не новости и не Ops):

```bash
sudo systemctl disable --now hermes-research-scout.timer
```

Нельзя отключать **связанный через symlink** `hermes-discovery.timer` ради теста. При частичной недоступности источника `status=HOLD`, сервис сигнализирует неуспех, но файл содержит причину; ни одной научной публикации не происходит.

## Научная достоверность и оставшиеся блокировки

Включённая **сборка открытых метаданных не является полностью автономным научным экспертом**. Для каждого потенциального вывода нужны PMID/DOI, методы (РКИ/наблюдательное/обзор), population, эффект и ограничения, проверка полного оригинала, лицензия/права на текст, доверенное подтверждение без двойного подсчёта и ручное разрешение публикации. Ни одно из этого автоматический извлекатель не утверждает.

Для внешней выдачи отчётов пользователю требуется отдельный утверждённый канал. Прямых изменений YFC, Second Brain или ночного AI Agent не производится. Этот read-only ежедневный процесс можно эксплуатировать независимо от отключённого постоянного Hermes Agent.


## Дополнительный этап H-03 от 15.10.2026

[PR #97](https://github.com/MikeMoore1337/hermes/pull/97) добавил ограниченную официальную проверку состояния публикации с реальным `HOLD` по коррекции IRONMAN (PMID `42771055`). По текущему изменению ежедневный отчёт выполняет **одну** такую проверку только для первого кандидата, которому выполнялся Crossref lookup; всего не более 5 GET за один запуск. Вторая, третья и другие записи **не прошли** эту проверку и помечены `NOT_CHECKED`. При недоступном API проверка становится `UNAVAILABLE`/`HOLD`, без рекомендации, автоматически не публикуется. Права владельца и серверные таймеры не меняются.


## Консервативный итог всего отчёта

Если **хотя бы одна** запись в отчёте имеет `HOLD` (исправление, отзыв, отсутствующий DOI, подозрительная публикация, конфликт или дубль), итог **всего** документа теперь `HOLD`. Так внешние потребители не перепутают наличие нескольких допустимых к дальнейшей ручной проверке записей с допуском **всех** публикаций. У записей без DOI `doi_missing` и `HOLD`, даже если в другом источнике DOI потенциально существует: это повод проверить связку PMID/PMCID, а не считать DOI доказанно отсутствующим. Все остальные статьи остаются отдельными `MANUAL_REVIEW` / `NOT_CHECKED`, научные выводы не подтверждены.


## Исправление календаря: один автоматический запуск в сутки

Ранее timer одновременно содержал `OnActiveSec=2min` и `OnCalendar=*-*-* 19:30:00`. Это давало дополнительный запуск через 2 минуты **после каждого запуска самого таймера** (например после установки или перезапуска), а также штатный календарный запуск, несмотря на название «ежедневный». Публичный сбор не становился платным, но число запросов за сутки переставало быть очевидным.

Теперь в таймере оставлен только `OnCalendar=*-*-* 19:30:00` (серверный часовой пояс), `RandomizedDelaySec=5min`, `Persistent=false`. Не выполняется автодогон после простоя и не происходит дополнительного старта при включении таймера. Установщик по-прежнему **явно** запускает ограниченную предварительную проверку службы один раз до включения расписания; этот тест не является регулярным запуском. Не использовать `disable` старых связанных таймеров новостей для проверки. После развёртывания сравнивать следующее штатное срабатывание через `systemctl list-timers`, не запускать принудительно службу.


## Защита целостности статусов перед записью (15.10.2026)

Перед атомарной заменой `latest-citations.json` повторно вычисляется общий статус отчёта по всем элементам и ошибкам. `HOLD` обязателен, если существует хотя бы один заблокированный кандидат или ошибка API. `NO_DATA` допустим только при пустых кандидатах и отсутствии ошибок; `MANUAL_REVIEW` - только при наличии кандидатов без `HOLD` и ошибок.

Каждый кандидат дополнительно проверяется по связке `status/reason/doi`: например, отсутствие DOI, устаревшая дата, подозрительное название или дублирующийся идентификатор не могут получить `MANUAL_REVIEW` при подмене поля статуса. Несовпадения запрещают сохранение, **не переписывают** существующий защищённый отчёт и не включают публикацию.

Регрессионные тесты сначала воспроизвели 14 несрабатывающих отрицательных проверок на прежней реализации, затем подтвердили отказ всех подмен после исправления. Весь Linux offline suite: **623/623 PASS**. Сетевой лимит, формат JSON, таймер, Telegram и YFC остались неизменными. Код в GitHub отдельно от факта установки на VPS.


## Дополнительный контроль календаря публикации при сохранении

Числовой формат `YYYY-MM-DD` сам по себе не доказывает существование даты (например, `2026-02-30`). При сохранении отчёта календарная дата теперь проверяется через `datetime.date.fromisoformat` даже у материалов со статусом `HOLD`. Для `MANUAL_REVIEW` дополнительно требуется фактическая дата публикации в пределах того же 30-дневного окна Europe PMC относительно `observed_at` (UTC), с однодневным допуском на публикацию в будущем из-за часовых поясов. Просроченная, невозможная или неопределённая дата не сохраняется как `MANUAL_REVIEW`; прежний защищённый отчёт не перезаписывается при отказе.

Это ограничение проверки происхождения и актуальности метаданных, а не автоматическая научная верификация. Запросы к API, Telegram, публикации YFC и расписание не изменяются.
