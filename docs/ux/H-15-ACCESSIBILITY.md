# Hermes Control Center: доступность и критерии приёмки (H-15 / #179)

Дата исходного аудита: 2026-10-18. База: `main` `db7ed22d4faef39af3d5aafa0cc6f20b91b23a3a`.
Scope: утверждённый **Atlas C+B с типографикой C+A**. Без редизайна, новых API, изменения OAuth, #33 runtime или production конфигурации.

## Что подтверждается кодом, а что нет

Исходный код уже содержит: `lang="ru"`, нативные `button`/`a`/`input`/`select`/`details`, `main`, именованную навигацию, подписи поиска и фильтра, текстовые состояния служб, `role="alert"` для ошибки снимка, `aria-current` во внутренней навигации, общие `:focus-visible` и `prefers-reduced-motion`. В React-источниках нет внешних шрифтов/CDN; в `public` есть manifest, иконки и third-party notices. Эти наблюдения **не доказывают полное WCAG 2.2 AA**.

Автоматические Playwright-контракты: `control_center/frontend/qa/accessibility.spec.js`. Они используют только локальный HTTP-сервер и синтетические снимки (не production), проверяют гостевой GitHub login, Tab/focus, именование полей, landmark, Space-навигацию, текстовые статусы, stale/API error, reduced-motion spinner, 320/393/1440 px. CI запускает их вместе с существующим `qa/control-center.spec.js` и тестами PWA. Запуск CI и ручная проверка фиксируются отдельно, не подменяются проверкой исходников.

## Выявленные недостающие проверки / возможные дефекты

1. **Пропуск повторяющейся навигации:** в `src/main.jsx` нет явной skip-ссылки на `main`; оценить требование 2.4.1 и добавить в доступный интерфейс, не меняя утверждённую компоновку. Любое видимое изменение focus state проходит visual approval владельца.
2. **Таблица:** `Registry` рендерит `table` без `caption`; на узком экране `thead{display:none}` и строки переводятся в flex. Проверить соответствие заголовков и ячеек в accessibility tree при 320 px и озвучивание скрытых колонок. Не считать адаптивный скриншот доказательством.
3. **Дублированная навигация:** верхние кнопки `.atlas-nav` имеют только класс `selected` (без `aria-current`), в то время как `Nav` уже выставляет `aria-current`. Проверить удобство двух наборов кнопок для screen reader и допустимое единое описание текущего раздела.
4. **Обновляемые данные и операторские виджеты:** отдельно проверить при истечении GitHub-сессии, неизвестной квоте, partial/stale telemetry и при смене раздела; отсутствие цветового-only состояния не доказывает, что новый статус озвучивается.
5. **Reduced motion/contrast:** измерить фактические цвета, прозрачные слои, hover/disabled/focus и анимации графиков. Автопроверка DOM не заменяет ручную цвето- и screen-reader приёмку.

Эти пункты - **результаты чтения исходного кода или непройденные acceptance gates**, а не утверждения, что дефект воспроизводился в production.

## Короткие правила для новых компонентов

- Нативные `button`, `a`, `label`, `details/summary`, `table` с `caption`/headers; ARIA - только там, где нужна дополнительная семантика.
- Каждая иконка-действие имеет доступное имя; декоративная SVG скрыта от accessibility tree.
- Состояние `UNKNOWN`, `NOT_CONNECTED`, `AUTH_REQUIRED`, `STALE`, `PARTIAL`, `BLOCKED` показывается словами, не только цветом. В отсутствие данных не показывать зелёный OK.
- Использовать существующие Atlas semantic CSS tokens; требовать 4.5:1 для обычного текста, 3:1 для крупного текста и необходимых границ UI согласно применимым исключениям WCAG.
- Новый блок проверять с клавиатуры и в узком viewport, 200–400% zoom, `reduced-motion`, ошибками/пустыми данными и реальным screen reader до заявления о WCAG 2.2 AA.
- Снимки для CI - только детерминированные fixtures, ясно помечать их происхождение. Никаких реальных токенов, пользовательских данных и сетевых запросов в обязательных визуальных тестах.
- Визуальные исправления → BEFORE/AFTER 320/393/1440 px и approval **до merge**; обновление тестов/документации без UI изменений можно принимать отдельно.

## Этап 2: точечные screen-reader исправления операторских виджетов

В ветке `fix/h15-179-widget-screenreader-20261019` изменены только автономные публичные JavaScript-виджеты и их копии в `control_center/web` (а не React layout, CSS, OAuth, CSP или runtime).

- **Desktop Commander:** вместо `aria-live` на всём списке устройств и истории графика используется один невидимый `role="status"`, сообщающий только о смене состояния или о недоступности API. Кнопка открытия по-прежнему передаёт фокус на «Закрыть», Escape возвращает фокус на «Устройства».
- **VPS infrastructure:** неизвестная нагрузка для `progressbar` явно имеет `aria-valuetext="Нет данных"` без поддельного `aria-valuenow=0`. При изменении доступности Hermes/YFC VPS озвучивается краткое текстовое резюме, одинаковый статус при опросах раз в минуту повторно не объявляется.
- **Provider quota:** отдельный невидимый `role="status"` объявляет фактические состояния четырёх источников; неизвестные и неподключённые квоты не называются доступными.
- **AI Usage Analytics:** статус частичной/неизвестной телеметрии получил `role="status"`, а на время обновления отмечается `aria-busy="true"`.
- **Регрессии:** `qa/widget-accessibility.spec.js` использует только синтетические данные, проверяет клавиатуру/Escape/focus restore, именованные live statuses, отсутствующие значения CPU без подстановки нуля и снятие `aria-busy`. Снимки production не нужны: расположение, тексты и CSS не менялись.

Проверенные этим этапом пункты не означают полной приёмки WCAG 2.2 AA. Реальный NVDA/VoiceOver, контраст, zoom/reflow, skip-navigation и семантика базового React Registry остаются отдельными условиями. Отметки PASS для точного HEAD/CI/production добавляются в Issue только после фактических результатов.


## Этап 3: точность неизвестных значений и контекст метрик (#179)

Изменения не затрагивают верстку, CSS, React-бандл, размеры иконок, авторизацию и сервисы. Исправлены три сценария в существующих автономных read-only виджетах:

1. **AI Usage Analytics:** при `completed_turns=null` вместо ошибочного `0` отображается «Число завершённых циклов неизвестно.»; достоверный `completed_turns=0` продолжает показываться как ноль.
2. **Мониторинг VPS:** каждому `progressbar` присвоено контекстное имя «VPS Hermes: CPU» или «VPS YFC: CPU» (аналогично RAM/Swap/диску/inode); SVG-графики истории содержат имя VPS в `aria-label`.
3. **Квоты провайдеров:** `progressbar` включает название источника, а `aria-valuetext` сообщает одновременно использованный процент и остаток. Неизвестные проценты остаются без числового `progressbar`.

`control_center/frontend/qa/metrics-accessibility.spec.js` проверяет эти состояния через изолированные фикстуры с неуспешными/неизмеренными значениями; production-метрики и private API не используются. Исходные JS в `frontend/public` и опубликованные файлы в `web` должны совпадать побайтово. Проверка точного коммита PR, CI и фактической production-доставки фиксируется в Issue по реальным результатам, не предполагается заранее.

Всё ещё открыты: исходная семантика React-таблицы и верхней навигации, skip link, полные замеры контрастности/масштабирования/целей касания, NVDA/VoiceOver, реальная авторизованная production-проверка. Для изменения видимого UI необходимы скриншоты и отдельное визуальное утверждение владельца.


## Этап 4: React navigation и native table semantics (#179)

В `src/main.jsx` верхние кнопки разделов получают `type="button"` и `aria-current="page"` для активного раздела, аналогично существующему `Nav`. Системная таблица получает невидимый нативный `<caption>` с доступным названием «Реестр системных служб и компонентов».

Для ширины до 560 px мобильный `thead` больше не имеет `display:none`. Заголовки остаются в дереве доступности и визуально скрываются через `clip`/`clip-path` с абсолютным позиционированием. Компактный двухколоночный внешний вид, надписи статусов, ограничения read-only и NO-GO не меняются.

`qa/semantic-accessibility.spec.js` проверяет доступное название таблицы, столбцы, текстовые строки системных состояний, обе навигации с клавиатуры, пустой/недоступный снимок на 320/393/768/1440 px.

**Приёмка:** для любого изменённого React/CSS обязательны точно пересобранные `control_center/web/app.js` и `style.css`, затем зелёный CI exact-head. Исходные скриншоты Atlas 320/393/1440 и сравнение до/после должны подтвердить отсутствие заметных визуальных отличий. Ссылка «Перейти к содержимому» - отдельный видимый по фокусу элемент и требует утверждения владельца до merge; в этой партии её нет.

Это **не** полноценное подтверждение WCAG 2.2 AA. Остаются реальные screen reader sessions, 200–400% zoom, текстовый контраст, 2.5.8 touch targets, OAuth/session expiration и production acceptance.
