# H-12: Agent Reach - ограниченная проверка без установки и сети

Статус: **оценка готовности / offline-only**, не production-интеграция.
Связано с [Hermes #64](https://github.com/MikeMoore1337/hermes/issues/64) (маркетинговые исследования) и [#4](https://github.com/MikeMoore1337/hermes/issues/4) (научные первоисточники).
Дата проверки: **2026-10-15**, upstream [Panniantong/Agent-Reach @ `94f06c1969dfc1834001269d79d3ad0972d9dee6`](https://github.com/Panniantong/Agent-Reach/tree/94f06c1969dfc1834001269d79d3ad0972d9dee6).

## Что фактически можно переиспользовать

Agent Reach v1.5.0 - средство установки, маршрутизации и диагностики внешних инструментов, **не** универсальный API для получения публикаций:

- `agent-reach doctor --json` возвращает готовность локальных каналов; статус **не доказывает** успешное чтение произвольной страницы или получение поисковых результатов.
- Встроенный MCP-сервер экспортирует только `get_status`, а не `read/search`.
- Веб-канал использует Jina Reader и помечает готовность без сетевого обращения; Exa через mcporter может означать лишь наличие записи конфигурации; GitHub CLI не подтверждает действительность авторизации.
- Библиографический Research Scout Hermes уже использует Europe PMC/Crossref. **Не внедрять** новые источники в штатные 5 GET/запуск, научные допуски или таймер.
- Second Brain уже обладает собственными `ExternalResearchPort`, Jina Reader, RSS, YouTube и GitHub адаптерами. Во время [v4 burn-in #386](https://github.com/MikeMoore1337/second-brain/issues/386) новые провайдеры не разрешены.
- SEO-контур и публикация принадлежат YFC #320/#322; Hermes #64 может лишь подготавливать гипотезы и черновики для человека.

Извлечение из соцсетей с авторизацией, cookies и браузерными сессиями **исключено**. Лицензия MIT у Agent Reach не отменяет условий использования сайтов и лицензий извлекаемых материалов.

## Что реализовано здесь

`content_research.agent_reach_preflight` принимает ограниченный JSON, ранее полученный оператором из `doctor --json`, и выводит безопасную сводку:

- фиксированный перечень пяти публичных кандидатов: `web`, `rss`, `youtube`, `github`, `exa_search`;
- статусы `LOCAL_CHECK_ONLY`, `NEEDS_MANUAL_CONFIGURATION_OR_PROBE`, `UNAVAILABLE`, `NOT_IN_REPORT`;
- явные `remote_read_verified=false`, `production_integration_approved=false`, `publication_allowed=false`;
- никаких входных сообщений `doctor`, raw URL, cookie, токенов и команд в выходном JSON;
- размер входных данных не выше 64 КиБ; некорректный ввод даёт фиксированную ошибку без отражения чужого текста;
- нет внешних зависимостей, сетевых запросов, запуска Agent Reach, записи в файл, чтения переменных среды или приватных ресурсов.

Это вспомогательная локальная **проверка перед испытаниями**, не новый fetcher, worker, сервис или инструмент резидентного агента. В обычных конвейерах Hermes он не подключён.

### Использование, только по решению оператора

Если Agent Reach **уже независимо установлен в тестовой среде**:

```bash
agent-reach doctor --json | python3 -m content_research.agent_reach_preflight
```

Для автономного локального теста допускается подать JSON-фикстуру в stdin без Agent Reach. **Не исполнять** `agent-reach install --system`, не импортировать полученный с GitHub `SKILL.md` в постоянно работающий агент, не добавлять провайдеры и учётные записи ради этой проверки.

### Тестирование

```bash
python3 -m unittest tests.test_agent_reach_preflight -v
python3 scripts/validate_repo.py
python3 -m unittest discover -s tests
```

Тесты для `preflight` полностью офлайн и используют синтетические записи; не сравнивают скорость, точность или реальную доступность Exa/Jina/YouTube.

## Функциональные границы и критерий следующего шага

| Направление | Решение | Что требуется прежде следующей реализации |
| --- | --- | --- |
| Hermes #64: публичный маркетинговый поиск | `CANDIDATE` | Разрешённый бесплатный источник, лицензия, формат результата, временные лимиты, реальные read-only испытания |
| Hermes #4: научные первоисточники | `NO_CHANGE` | Подтверждение необходимости сверх Europe PMC/Crossref, корректность DOI/retraction/лицензий, ручная проверка |
| Second Brain v4 | `NO_CHANGE` | Только доказанная потребность в ходе burn-in #386 и отдельное owner-решение |
| YFC | `NO_CHANGE` | Отдельная задача владельца YFC и редакционное утверждение |
| Resident Hermes #33 | `NO_GO` | Сохранить существующий блокирующий security gate без новых shell/MCP/tools |

**Итог:** реализован только изолированный, полезный для оценки каналов offline preflight. Ни интеграция источников, ни подлинная их доступность, ни работоспособность на VPS, ни бесплатность внешних сервисов пока **не подтверждены**.
