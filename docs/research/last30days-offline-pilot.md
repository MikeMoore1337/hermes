# Hermes #542 - пилот анализа обсуждений за 30 дней

Связь с задачей: https://github.com/MikeMoore1337/hermes/issues/542

В Hermes Research Scout уже есть научно-библиографический контур. Анализ обсуждений - **отдельный тип данных**: популярность заметки/PR не подтверждает качество исследований, безопасность рекомендаций или необходимость менять YFC.

Внешний источник идей: [mvanhorn/last30days-skill](https://github.com/mvanhorn/last30days-skill), лицензия MIT по опубликованному репозиторию. **Внешний скилл, скрипты, провайдеры и зависимости не устанавливаются и не копируются.** Ветка содержит только оригинальный, маленький офлайн-эксперимент.

## Что уже реализовано в исходниках

`content_research/discussion_digest.py` принимает список готовых сообщений с полями `source`, `url`, `title`, `published_at`, `retrieved_at`, `score`, плюс явно переданное `now` с часовым поясом. Поддерживаются только публичные ссылки на конкретные GitHub Issues/PR/Discussions и Hacker News items.

Алгоритм:
- отклоняет неизвестные источники, небезопасные адреса, дополнительные поля, будущие/некорректные даты, огромные оценки и неполные записи;
- применяет **точный временной диапазон в 30 суток**, включая граничную дату;
- исключает устаревшие сообщения и объединяет записи по исходному URL (конфликтующие метаданные - ошибка);
- сортирует по наблюдаемой оценке обсуждения (она **не научный рейтинг**) и URL для воспроизводимости;
- возвращает происхождение каждой записи, причины исключений в агрегированном виде и флаг `scientific_evidence=false`;
- не читает учётные данные и приватные файлы, не делает запросов, не пишет в другие проекты, не публикует сообщения и не использует модели.

Проверка с Python из корня Hermes:

```bash
python -m unittest tests.test_discussion_digest -v
```

Это только детерминированная логика на искусственных данных. GitHub/Hacker News API, реальная релевантность, качество ранжирования, ограничения частоты и точность дат внешних источников **NOT_TESTED**. Поле `score` приходит извне без автоматической верификации. Список наблюдаемых источников пока не подключён.

## Следующий этап до возможного включения

1. Сравнить этот подход с существующими новостными и исследовательскими материалами: количество уникальных пригодных сигналов, дублей и ложных совпадений по заранее выбранной выборке.
2. Если польза доказана, отдельно спроектировать разрешённый read-only клиент публичного API с фиксированным хостом, лимитом запросов, размером ответа, timeout, DNS/IP SSRF-защитой и датой наблюдения.
3. Отдельно согласовать расписание, ретенцию, любые уведомления и эксплуатационную доставку. Полный сторонний Last 30 Days, Polymarket, финансовые источники, платные модели и социальные ключи не входят в эксперимент.

Вердикт текущего этапа: `OFFLINE_EXPERIMENT`, не `PRODUCTION_READY`. Никаких утверждений о реальном улучшении поиска или фактическом бесплатном использовании провайдеров.

## Реальный публичный снимок Hacker News (opt-in)

Добавлен `content_research/hn_public_probe.py`: один ограниченный HTTPS GET к публичному [HN Search powered by Algolia](https://hn.algolia.com/api) через фиксированный хост `hn.algolia.com`. Это поисковая инфраструктура Algolia, **не официальный Firebase API Hacker News**, и доступность без ключей не гарантируется навсегда. Никакого произвольного URL/поискового текста снаружи и никакого обхода блокировок.

```bash
python -m unittest tests.test_discussion_digest tests.test_hn_public_probe -v
python -m content_research.hn_public_probe --topic ai-agents
# ТОЛЬКО при явном намерении сделать один публичный запрос:
python -m content_research.hn_public_probe --topic ai-agents --execute
```

Разрешены три фиксированные темы: `ai-agents`, `python-qa`, `fitness-tech`. Каждый запуск с `--execute` делает максимум один запрос, максимум 12 записей с 10 или более голосами, лимит ответа 96 KiB, сетевой таймаут 6 секунд, IP должен быть публичным, TLS-сертификат проверяется для исходного имени хоста, HTTP redirect блокируется; без повторов, без токенов, подписок, публикаций и планировщика. Отдельно проверять возможные ограничения поискового сервиса и требования его использования.

Отчёт - **не полнота за 30 дней**, а ограниченная выборка по поисковой теме и свежести. Заголовки и количество голосов приходят от публичного сервиса, не подтверждены независимым источником. Репутация/популярность != научная доказательность. Если сервис недоступен, статус `NOT_AVAILABLE`, никаких автоматических fallback.

Чтобы решить, нужна ли функция Hermes, нужно сравнить выборку с тем, что уже выдаёт Research Scout, по практической полезности. Эти контуры работают с **разными классами данных**, поэтому не считать разницу количества ссылок доказательством эффективности.

Пробный публичный запрос от 23.10.2026 (UTC) подтвердил, что фильтр Algolia `created_at_i>=... ,points>=10` возвращает релевантные обсуждения с наблюдаемыми оценками, но это всё ещё первые 12 **недавних** записей по запросу, не глобальный рейтинг и не полный месяц. Точная тематика и оценки со временем меняются. Не называть выборку доказанными трендами.
