# H-15 / #208 — проверка узкого egress для GitHub OAuth

**СТАТУС: REVIEW ONLY, не разрешено менять production IPAddressAllow или запускать OAuth.**

## Назначение

`scripts/h15_oauth_egress_evidence.py` проверяет **снимок наблюдений**, а не конфигурирует сеть. Ввод — локальный JSON, независимо полученный через доверенный канал в короткий промежуток времени:

```json
{
  "source": "https://api.github.com/meta",
  "captured_at": "2026-10-16T18:55:00Z",
  "ranges": {
    "web": ["<CIDR-подсети из актуального ответа meta.web>"],
    "api": ["<CIDR-подсети из актуального ответа meta.api>"]
  },
  "resolved": {
    "github.com": ["<фактические DNS A/AAAA этого хоста>"],
    "api.github.com": ["<фактические DNS A/AAAA этого хоста>"]
  }
}
```

Угловые скобки **только образец полей**. Не копировать их в рабочий JSON. Скрипт не делает HTTP, DNS или чтения секретов. Не принимает произвольные домены. Проверяет 15-минутную свежесть, точную схему, глобальные IP, включение каждого resolved IP в соответствующие официальные диапазоны и отказывается от метаданных с чрезмерно широкими префиксами. На выходе только кандидаты `IPAddressAllow=a.b.c.d/32` или `/128`, но не готовый systemd drop-in.

**Источник диапазонов:** <https://docs.github.com/en/rest/meta/meta> (актуальные реальные диапазоны только от `https://api.github.com/meta`, данные документации не фиксируют постоянные IP).

## Обязательные проверки, ещё НЕ пройденные

- Достоверность источника и репрезентативность DNS на самом VPS, включая IPv6 и DNS changes.
- Системная загрузка секретов через `LoadCredential` под отдельно ограниченными `hermes-control` и `hermes-oauth` UID без переноса secret в web env. Права `0700/0600` и строгая конфигурация проверены ранее, но **не** сама загрузка через systemd.
- `systemd-run` с cgroup-deny-all и *временным* набором только целевых /32-/128, **проверка TLS server hostname** к обоим разрешённым host endpoints (без OAuth secret). Негативный тест к `1.1.1.1`, `8.8.8.8` и сторонним GitHub endpoints в той же cgroup, без внешнего доступа веб-службы.
- Защищённый канал логирования: Caddy/Cloudflare не должны сохранять `code` и `state` в raw URL callback. Нужна проверка конфигурации и негативные тесты на синтетическом маркере, без отправки действительных OAuth кодов.
- Успешная авторизация владельца и отказ другого GitHub ID, истечение/отзыв сессии, rollback. Только после этого отдельное OWNER GO и изменение Caddy Basic Auth.

## Ограничения

Проверка попадания в GitHub CIDR не доказывает единоличное владение адресом или неизменность DNS. Фактическое ограничение запросов достигается сочетанием отдельной systemd IP-политики, фиксированных HTTPS URL/методов на уровне брокера, сертификатов и ограниченного Unix RPC. При смене DNS за пределами списка допустим **только отказ**, а не временное разрешение всей сети.

**Никогда не вводить Client Secret в CLI arguments, Github issues, PR или CI.**

Состояние безопасности на 16.10.2026: у владельца установлен отдельный OAuth App и два файла credentials; подтверждены root `0700/0600`, общий числовой owner ID и отсутствие секретов в web.env. Активная панель остаётся под Basic Auth, `IPAddressDeny=any`, Resident Agent #33 NO-GO.
