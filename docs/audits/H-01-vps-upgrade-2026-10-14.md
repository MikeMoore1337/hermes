## 3. Границы подтверждённой безопасности

Подтверждено: immutable image digest (v0.21.6), реальный Linux пользователь и private data home, конфигурация контейнера без host network/ports, readonly rootfs, no additional capabilities, отсутствие иных mounts по inspect, ненаступление отказа существующего timer в момент теста, безопасный timeout/cleanup, отсутствие live credentials в тестовом запуске.

**Ещё НЕ доказано:** полноценный sandbox escape/egress penetration test, нагрузка в пике при одновременных news discovery/drain, долгосрочная стабильность gateway, обновление/rollback под моделью, корректность OAuth/provider и доступов, доставка реальных предупреждений, реальный путь разрешённой сети.

Один пробный вызов оболочки для проверки путей из контейнера столкнулся с преобразованием командной строки через Windows SSH и не дал достоверного результата; **его нельзя учитывать как прошедший отрицательный тест доступа к файлам**. Границы Docker inspect при этом подтверждены отдельно. Отрицательные тесты необходимо запускать воспроизводимым проверенным скриптом до включения возможностей агента.

## 4. Решение и блокировки

- Решение использовать существующий VPS и расширенную RAM **выполнено**; 4 ГиБ RAM достаточно для короткого изолированного запуска с выставленными лимитами. Это **не гарантия** одновременной круглосуточной работы всех подсистем.
- Production новостного Hermes остался независимым в YFC, без миграции и изменения release.
- Текущая проверенная версия Docker v0.21.6 остаётся закреплённой. 2026-10-14 доступен upstream v0.22.0, его переход требует отдельной проверки. Сохраняется известное расхождение между CLI embedded upstream SHA a28a5d03 и GitHub annotated release commit 818c13be.
- **H-01 остаётся OPEN:** нет отдельного утверждённого model/provider, изолированного разрешённого egress к нему, ключей, длительного стресс/эндюранс теста и функционального агентного прохода. Ничего не переиспользовано из секретов редакционного worker.
- **H-02 частично реализован офлайн** в [PR #13](https://github.com/MikeMoore1337/hermes/pull/13): только детерминированный аналитический движок, без collectors, уведомлений или расписаний.

**Следующая техническая последовательность**: согласовать отдельно модель/стоимость/возможность бесплатного доступа -> ограниченная сеть к одному провайдеру, секреты только в выделенном sandbox -> контролируемый functional smoke -> read-only Ops Watch collector -> уведомления только после согласования канала -> замеры под реальной нагрузкой -> только затем systemd enable и более продолжительная эксплуатация. До прохождения этого этапа оставлять новую службу disabled.
