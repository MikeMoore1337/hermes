Контейнер на новом upstream **не пройдёт** эту проверку без нового пересмотра bounded native-tool patch/provenance. Менять pin/guard автоматически недопустимо.

## 3. Решение и контур будущего upgrade

**KEEP_PINNED:** сохраняем текущий v0.22.2-derived restricted image. Это сознательное архитектурное решение, а не утверждение, что v0.22.4 небезопасна или хуже. Никакая функциональная задача, ради которой требуется срочный upgrade, **не доказана**; при этом разница в 3030 коммитов, меняющийся lockfile, добавление plugin/OAuth/MCP boundary и фиксированный `bounded-v0222` patch требуют отдельного review.

Для возможного отдельного controlled upgrade необходимо, в указанном порядке:

1. **Independent evidence:** полный changed-file/dependency/license review через локальные pinned git objects (GitHub compare 300 files недостаточен); проверить фактические native tool/MCP/plugin/settings API contracts и эффект именно на #33/#350; подготовить карту патчей и изменения policy, CVE входит в отложенную #199.
2. **Supply chain:** pinned candidate commit + review Dockerfile/build workflow + независимо проверенный local-image SHA и expected OCI labels. Никаких `:latest`, `:stable`, внешнего `curl | sh` или trust-on-first-use.
3. **Offline A/B:** на отдельных fixture/test окружениях подтвердить разрешённые/запрещённые вызовы (MCP readOnly, privileged OS/file reads, cross-project isolation), local gateway reboot/lock + plugin consent and rollback; фиксировать negative cases, private boundary, exact commit и unit/e2e oracle; без оплаты моделей.
4. **Operator gate:** отдельное согласование перед *активацией* candidate, status H-01 #33 и H-19 #350, реальные ресурсы 2 vCPU/2 GB, owner-reviewed rollback и staged one-shot canary, без отключения работающего Control Center.
5. **Production:** новая image provenance receipt, exact CI/rollback и host-level доказательство только после GO; не считать source merge доказательством живого upgrade.
