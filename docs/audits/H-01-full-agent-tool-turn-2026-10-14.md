# H-01: два успешных реальных Agent-turn на VPS - 2026-10-14

**Дата:** 14 октября 2026, реальный Hermes VPS. **Версия:** NousResearch Hermes v0.21.6, immutable amd64 digest sha256:32d095e84190ae7266afbb361579e6921f2c633e899f5eacfb88111b9c851a22. **Провайдер:** Cloudflare Workers AI Free, @cf/openai/gpt-oss-20b, отдельно от новостей YFC.

## Доказательства

1. **До запуска** первая попытка при load1=3.73 закончилась preflight SKIP, без запуска нового агента. Это ожидаемое fail-closed поведение, не ошибка модели. После снижения нагрузки до 0.38 проверка была разрешена.
2. **[PR #27](https://github.com/MikeMoore1337/hermes/pull/27)** - bounded explicit Hermes -z (не двусмысленный старый chat --oneshot), todo-only toolset. Реальный успешный текстовый ответ OK: **status=pass, exit_code=0, 108.1 секунды, 1 строка ответа**. Лимиты 0.30 CPU / 640 MiB RAM / 896 MiB memory+swap. Флаги auth, quota, network, HTTP400, PM-lock - false.
3. **[PR #28](https://github.com/MikeMoore1337/hermes/pull/28)** - отдельный безопасный запрос на применение in-memory todo_list. Успех засчитывается **только** после сравнения количества записей о вызовах/результатах инструмента в независимой SQLite state.db до и после. Реальный результат: **status=pass, exit_code=0, 112.1 секунды**, ожидаемый итоговый текст TOOL_OK и **5 новых строк**, в которых присутствует todo_list. Эти **5 строк не равны обязательно пяти уникальным вызовам**: подсчитываются и сообщения ассистента с описанием вызова, и сообщения результата инструмента. Не сообщать как «5 tool invocations».
4. В ходе второго испытания примерно через минуту load1 составлял **0.47**, а после run **1.02** (охранный порог новостей 1.5; внутренний максимум для новой задачи 1.3). После теста MemAvailable **2376 MiB**, swap used **0**, новостной `hermes-discovery.timer` и `hermes-ops-watch.timer` оба **active**, ресурсный guard **ready**.
5. После каждого теста нет запущенного agent gateway; ограниченный Cloudflare CONNECT proxy **inactive**. Ошибок квоты, аутентификации, HTTP400, провайдера или PM-lock в очищенном результате нет. Сырые API-тексты и секреты не размещены в PR, GitHub Issues, консоли и итоговом отчёте.

**Что именно доказано:** реальный Hermes CLI, Cloudflare Free, модель GPT-OSS 20B, два последовательных на практике независимых bounded запуска (ответ и инструмент), реальный зарегистрированный вызов инструмента todo_list, локальные CPU/память и сохранение работоспособности двух текущих таймеров.

**Что НЕ доказано:** устойчивость круглосуточной работы, запуск после reboot без потери nft-правил, нагрузка при максимальном пике news discovery/drain, автономные уведомления/Telegram, внешнее чтение GitHub/YFC/Second Brain, платёжный биллинг за несколько суток. Отсутствие явной 429 в этих двух тестах не является исчерпывающим испытанием всех отказов провайдера. Старт каждого CLI turn занимает **~110 секунд при 0.30 CPU**, это существенно для интерактивности; постоянный gateway может амортизировать запуск, но ещё не утверждён.

**Security:** изолированный --internal Docker bridge, nft вход/передача по deny-by-default, ограниченный Cloudflare-only CONNECT proxy, отсутствие host Docker socket и приватных YFC/Second Brain mounts, отдельная учётная запись, приватные credentials 0600, никаких платных fallback. Текущий CONNECT proxy проверяет CONNECT authority, но без TLS termination не доказывает строгую SNI-фильтрацию против злонамеренного клиента. Не расширять набор инструментов до shell/code/browser без отдельного усиления изоляции.

**Статус:** проблема зависания краткого диагностического CLI в #24 устранена функционально, но acceptance H-01 #2 и 24/7 эксплуатация **не завершены**. Оставить полный автономный Hermes gateway **disabled/inactive** до дополнительных negative tests, reboot/net recovery и устойчивости.
