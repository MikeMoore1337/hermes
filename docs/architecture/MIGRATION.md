# Перенос Hermes из YFC: политика и порядок

**Статус: план, не разрешение на миграцию.**

**Решение по Issue #7 на 2026-10-19: `KEEP_CURRENT`.**
[Архитектурная приёмка и evidence matrix](../decisions/H-07-news-runtime-ownership-2026-10-19.md).
YFC остаётся владельцем специализированных news discovery/worker, release и
scheduler, физически расположенных на выделенном Hermes VPS. Перенос в
репозиторий Hermes Agent не выбран. Следующие пункты - **условный**
runbook для будущей отдельно разрешённой миграции, а не инструкция
активировать второй runtime. Новый read-only VPS receipt по состоянию на
2026-10-19 отсутствует.


## Что сейчас остаётся в YFC

Файлы `deploy/hermes-discovery/`, `deploy/hermes-editorial-worker/`, `scripts/hermes_*.py`, API intake, source registry, новости и публикация остаются там, где сейчас. Их нельзя копировать сюда как второй изменяемый источник истины.

## Перед любым cutover

1. H-00: инвентаризация хостов, активных сервисов, точных SHA/image digests, таймеров, ресурсов, секретов и сетевых маршрутов. Проверить реальные исходы релизов, не использовать только Issue как доказательство текущего production.
2. Зафиксировать owners: кто генерирует source definitions, кто выпускает images, кто владеет intake/review и кто включает timer.
3. Версионировать JSON/HMAC/identity/ingestion contract и доказать совместимость обеих сторон, включая дедупликацию и исторические manifests.
4. Отдельная среда/профиль, проверки secret/egress isolation, отсутствие доступа к YFC DB или приватному vault, негативные тесты.
5. Проверить ветку миграции без изменения действующего timer: локальные тесты, shadow без публикации и нагрузочные границы.
6. **Отдельный owner GO** перед stop/start сервисов, выдачей секретов, изменением egress или переключением графа доставки.
7. Однократное переключение владения расписанием с контролем отсутствия двух активных исполнителей, наблюдение, подтверждённый health/smoke и план возврата.
8. Удалять legacy только после подтверждённого успешного периода и отдельного PR/CI; до этого сохранять проверенный rollback.

## Запреты

- Без «сначала скопируем, потом разберёмся»: это создаст два running workers и риск дублирования.
- Не переносить YFC бизнес-правила или приватные данные в Hermes.
- Не менять существующий Telegram tunnel, сеть, порт и хост по инерции.
- Никаких автоматических действий из этого документа.
