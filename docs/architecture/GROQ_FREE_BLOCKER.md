# Groq Free и автономный Hermes: проверенные ограничения

Актуально на **2026-10-14**. User-approved provider: отдельный **Groq Free**, без биллинга/paid fallback, секреты редакционного YFC запрещено переиспользовать. Нового `GROQ_API_KEY` для независимого Hermes в собственном хранилище `/var/lib/hermes-agent/.env` **пока нет**.

## Проверенные факты

1. [Официальная история отключений моделей Groq](https://console.groq.com/docs/deprecations): `llama-3.3-70b-versatile` и `llama-3.1-8b-instant` отключены на Free/Developer **16 августа 2026**. Ранее планировавшаяся Llama 3.3 70B не годится.
2. [Текущие официальные лимиты Groq](https://console.groq.com/docs/rate-limits): `openai/gpt-oss-20b` и `openai/gpt-oss-120b` имеют базовые Free **8,000 tokens/minute, 30 requests/minute, 1,000 requests/day, 200,000 tokens/day** (точные ограничения конкретного аккаунта могут быть другими). Лимиты действуют на организацию, не на отдельный ключ.
3. [Официальный каталог Hermes Groq provider](https://hermes-agent.nousresearch.com/docs/plugins/groq-provider): Community MIT v1.0.0, pinned reviewed `b5be038`. Стандартный custom endpoint для GPT-OSS в Hermes v0.21.5 отправляет `reasoning_effort`, который Groq отклоняет HTTP 400; плагин умеет нормализовать reasoning и фильтровать модели. Это сторонний код: читать и проверять до установки.
4. Каталог [предупреждает](https://hermes-agent.nousresearch.com/docs/plugins/groq-provider), что сам стандартный набор инструментов Hermes может дать **18.8k токенов на запрос**, и даже один набор - 10.7k-11.7k, что **превышает** 8k Free TPM. Поэтому даже с отдельным ключом полноценный инструментальный Hermes с этой конфигурацией вероятно будет получать **HTTP 413**. Уменьшение числа включённых toolsets и реальное измерение возможны, но **не доказаны** достаточными для автономных задач.
5. На дату проверки опубликован [Hermes v0.22.0](https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.0), но фактически протестированный на выделенном VPS runtime - pinned **v0.21.6**. Нельзя автоматически обновлять до `latest`; сначала отдельная security/release validation.

## Безопасный маршрут подключения

1. В [Groq Console](https://console.groq.com/keys) владелец создаёт **отдельный проект/ключ** для Hermes на тарифе Free; отключает/не подключает платную тарификацию. Рекомендуемый тестовый текстовый вариант - `openai/gpt-oss-20b` с подтверждённым доступом в аккаунте. Ключ не размещать в GitHub Issue, чатах, CI или отчётах.
2. Инъекция ключа **только** в приватное хранилище нового агента, `/var/lib/hermes-agent/.env`, права `0600`, владелец `hermes-agent`. Не копировать ключ из `/etc/hermes`, редакционного worker или других проектов.
3. В отдельном PR выбрать и проверить закреплённую версию MIT `groq-provider` или валидацию новых параметров upstream; модель не изменять во время релиза без подтверждённого smoke.
4. Перед разрешением внешней сети доказать egress только на `api.groq.com:443` (в отличие от общего Docker bridge), отсутствие доступа к YFC/Second Brain, 429/413 fail closed, бюджеты и ограничение количества запросов. Не использовать универсальные subscription gateways.
5. Запустить **небольшой текстовый** запрос без инструментов и проверить модель, реальный счётчик и отсутствие расходов. Для tool use измерить число токенов фактического запроса; если Free TPM недостаточен, **остановить включение автономных заданий** и запросить отдельное решение. Платный тариф не подключать автоматически.

**До выполнения этих условий** отдельный `hermes-agent-sandbox.service` оставлять **disabled/inactive**. Нынешний локальный Ops Watch способен продолжать работу без LLM, но не заменяет полноценного Hermes Agent.
