# Контракты, источники истины и границы владения

| Домен | Канонический владелец | Hermes может | Hermes не может |
|---|---|---|---|
| Новостные источники YFC | `your-fitness-coach/backend/fitminiapp_api/resources/news_sources.json` | Читать утверждённые версии | Самостоятельно редактировать второй список источников |
| Редакторская проверка, медицинские утверждения, публикация | YFC backend и owner review | Подготовить подписанный совместимый черновик через существующий boundary | Публиковать в обход YFC |
| Runtime новостного discovery/worker | Сейчас YFC | Подготовить план миграции и тесты | Непроверенно менять активные systemd/Docker сервисы |
| Vault, NoteDraft, Safe Write | `second-brain` + отдельный приватный vault | После разрешения читать только специализированный API и предлагать изменения | Чтение приватного git/FS и прямая запись в vault |
| Общие роли Hermes, custom skills, мониторинг, исследования | `hermes` (после реализации) | Управлять только собственными компонентами | Получать доступ к чужому runtime по умолчанию |
| PR/CI/deploy YFC | YFC GitHub Flow | Анализировать read-only результаты | Самостоятельно merge, push в YFC или deploy |

При миграции ownership runtime изменится только по задокументированному cutover. До этого ни CI, ни deployment pipeline не должны запускать два владельца одного расписания или публикации.

Не хранить копии контрактов, ключей и данных пользователя только ради удобства для агента. Указывать ссылку на канонический документ и, где нужно, версию/хеш контракта.
